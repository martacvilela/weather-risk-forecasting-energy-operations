## LinkedIn post

I’ve just completed a new applied AI / Data Science portfolio project: **Weather Risk Forecasting for Energy Operations**.

The goal was to build a realistic machine learning prototype for an industrial use case: predicting whether daily weather conditions are safe or unsafe for outdoor energy operations affected by wind, rainfall and temperature.

The project includes:

- Python, Pandas and NumPy for data processing
- Feature engineering from meteorological variables
- Binary classification with Logistic Regression, Random Forest and XGBoost
- Evaluation using accuracy, precision, recall, F1 and confusion matrices
- Visual storytelling for operational decision support
- A GitHub-ready modular structure and optional Streamlit prototype

What I wanted to demonstrate is not just model training, but the full applied workflow: translating a physical operational problem into a supervised ML task, defining a clear target variable, evaluating model behaviour and communicating results in a way that could support real decision-making.

This project also reflects the direction I’m aiming for professionally: junior / graduate roles in AI, Data Science, Applied AI and industrial analytics, especially where data, physics and energy operations intersect.

## Why this demonstrates junior AI / Data Science capability

This project is credible for a junior profile because it does not overclaim production-level forecasting. Instead, it demonstrates the foundations that employers expect:

1. Problem framing: the project converts an operational energy-sector question into a binary classification problem.
2. Data handling: it includes cleaning, missing-value treatment and feature preparation.
3. Feature engineering: the variables are linked to real physical risk drivers such as wind gusts, precipitation and thermal stress.
4. Model comparison: it evaluates a simple interpretable baseline and stronger non-linear models.
5. Evaluation thinking: it uses multiple metrics and highlights why recall matters when missing unsafe days has operational consequences.
6. Communication: the README, plots and project narrative are written for technical and non-technical readers.
7. Reproducibility: the repository is modular and executable, not only a notebook.
